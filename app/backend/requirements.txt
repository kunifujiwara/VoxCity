# The backend imports voxcity only through public names, and the names it
# needs first exist at 1.6.0: the voxcity.geoprocessor.geojson module (the
# GeoJSON builders + get_lc_source_colors, promoted out of the ipyleaflet-heavy
# draw package) and the package-level re-exports the app switched to
# (compute_grid_geometry / compute_cell_center_coords in geoprocessor.raster,
# generator/downloader/visualizer/utils/exporter re-exports). Against an older
# voxcity the app fails at import time -- and a split-out app installing from
# PyPI would otherwise silently resolve a private-import-era build. Today the
# app runs from this repo checkout (PYTHONPATH), so this line is a declaration
# of the floor, not how voxcity is installed.

# PLATEAU LOD2 mode requires the VoxCityGML package (separate repo):
#   pip install -e <path-to-VoxCityGML>   (https://github.com/kunifujiwara/VoxCityGML)
#
# It must be a build that supports *rotated* target rectangles, i.e. one whose
# grid_utils.GridParams carries the affine grid frame (origin_lon/origin_lat +
# the e_col_*/e_row_* basis vectors). That support shipped in voxcitygml 0.3.0.
#
# The version is not the gate, though: the backend probes GridParams for those
# fields at runtime and reports LOD2 unavailable without them. An editable
# install from a git checkout — the normal setup here — records whatever
# version `pip install -e` happened to see, so its metadata routinely lags (or
# leads) the code actually on disk; only the structure is trustworthy. Getting
# this wrong is silent rather than loud: a pre-rotation build grids a rotated
# rectangle as its axis-aligned bounding box without raising. Update the
# checkout and reinstall if /api/health says the package predates rotation
# support.
